# Module 62: DSA and Coding

Build repeatable problem-solving habits for interviews and daily engineering. Focus on explaining the solution, complexity, trade-offs, and edge cases instead of memorizing answers.

## Learning Order

1. Arrays, hashing, two pointers, sliding windows, prefix sums, and frequency counting.
2. Strings, linked lists, stacks, queues, and monotonic stacks.
3. Trees, graphs, BFS, DFS, topological sorting, and shortest paths.
4. Binary search, sorting, recursion, greedy techniques, and dynamic-programming basics.
5. Time, space, and amortized complexity across all solutions.

## Practice Deliverable

Solve 25 curated problems. For each, record the problem source/link, constraints, brute-force idea, chosen approach, complexity, edge cases, tested examples, and a spoken explanation. Reimplement selected problems after a delay without looking at the original solution.

## Completion Criteria

- [ ] Identify the data structure/algorithm family from constraints rather than keywords alone.
- [ ] State time and space complexity accurately.
- [ ] Test empty input, one item, duplicates, boundaries, and invalid assumptions.
- [ ] Explain an alternative approach and why it was not selected.
- [ ] Solve several previously completed problems again from memory.

## Common Mistakes

Optimizing before understanding constraints, skipping edge cases, confusing recursion depth with time complexity, using a known pattern without proving it fits, and presenting code without explaining invariants.
