# React: Modules 31-33

Build the TeamOps client in three steps: compose accessible UI, connect it to the Go API, then make its behavior secure, testable, and efficient. Follow the [React Learn documentation](https://react.dev/learn), the [React TypeScript guide](https://react.dev/learn/typescript), and the [Hands on React TypeScript labs](https://handsonreact.com/docs/labs/react-tutorial-typescript).

## Dependency Map

```text
30 typed JavaScript and API contracts
    -> 31 components, props, state, forms, and accessibility
    -> 32 routing, data fetching, authentication, and server integration
    -> 33 tests, performance, client security, and production behavior
```

## Shared Completion Standard

Each feature must represent loading, success, empty, error, and unauthorized states when applicable. Keep server data, local UI state, and derived values distinct. Favor simple components and inferred hook types; add explicit types when inference cannot express the domain state clearly.

## Hands-On Lab Path

Use the Hands on React labs as a progressive practice reference: project setup, CSS, components, data, props, lists, events, forms, validation, REST, routing, custom hooks, query refactoring, and tests. Rebuild the concepts against TeamOps requirements instead of copying the tutorial solution.
